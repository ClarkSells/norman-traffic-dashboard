# Norman Traffic Case, Research Scout

Compiled 2026-11-05. Every ArcGIS endpoint below was probed live with `?f=pjson` and a count query unless the row says otherwise. Field lists are the actual service schemas. Norman bbox used for "n in Norman" counts: lon -97.55 to -97.17, lat 35.14 to 35.35 (envelope, so it slightly over-counts along the city edge).

Legend for "Status": LIVE = fetched and parsed this session. REACHABLE = HTTP 200 but not parsed. BLOCKED = could not be fetched from this environment (reason given). KNOWN = well established resource, URL from search result or prior knowledge, not re-fetched.

Already in the pipeline (from `config.py`): `Council_Wards/FeatureServer/1`, `Street_Centerlines/FeatureServer/1`, `Proposed_Functional_Classifications/FeatureServer/1`. Everything else in section A is new.

## A. Data sources

### A1. City of Norman ArcGIS Online, full service inventory

Org id `rt1leD4Hj3sLGHNL`. Services root: `https://services.arcgis.com/rt1leD4Hj3sLGHNL/arcgis/rest/services?f=pjson` (LIVE, 367 FeatureServers). Hub front door: https://norman-gis-open-data-normanok.hub.arcgis.com. Dataset pages follow `https://norman-gis-open-data-normanok.hub.arcgis.com/datasets/normanok::<slug>/about` and the "I want to use this" panel exposes GeoJSON, CSV, Shapefile, KML and the GeoService URL.

License note (LIVE from item metadata): Street Centerlines and Council Wards items carry the City's boilerplate "All data are provided as is, with all faults, and without warranty of any kind". No attribution clause, no non-commercial restriction. Portal name "City of Norman", urlKey `normanok`.

Query pattern that works for every layer below:

```
<FeatureServer>/<layer>/query?where=1%3D1&outFields=*&outSR=4326&f=geojson&resultOffset=0&resultRecordCount=2000
```

Page with `resultOffset` until `exceededTransferLimit` is absent. Norman services have `maxRecordCount` 1000 or 2000. Add `&geometry=<bbox>&geometryType=esriGeometryEnvelope&inSR=4326&spatialRel=esriSpatialRelIntersects` to clip.

#### What the Norman org does NOT publish (checked by name across all 367 services and by Hub search)

- No traffic signal point layer. The Traffic Division page says the City maintains "more than 168 traffic and pedestrian signals" and 24 TMC cameras, but no GIS layer is public. Partial substitute: `ADA_Transition_Plan_GIS_Data` layer 1 `Signalized` field, OSM `highway=traffic_signals` (see A6), and the ACOG crash table's `Intersection_Control` = "Traffic Signal" (see A3), which lets you infer signalized nodes from crash records.
- No traffic count layer. The Traffic Division page (LIVE) states: "The City of Norman used to publish traffic count maps but stopped several years ago" and that counts now go to ACOG's TCDS. Archived PDFs: 2009 `https://www.normanok.gov/sites/default/files/documents/2020-04/Norman%202009%20Traffic%20Count%20Map.pdf`, 2007 `.../Average%20Daily%20Traffic%20Count%20Map%20for%202007.pdf`, 2005 `.../Average%20Daily%20Traffic%20Count%20Map%20for%202005.pdf`.
- No posted speed limit layer beyond `Street_Centerlines.SpeedLimit` and `LegalSpeed`.
- No bike lane layer on the Norman org. Use ACOG `Low_and_High_Stress_Bike_Infrastructure_ACOG_TMA_2026` (A3), which has 201 Norman features with CATEGORY, StressLev and ADT.
- No bridge inventory. Use FHWA NBI (`https://www.fhwa.dot.gov/bridge/nbi/ascii.cfm`, KNOWN) filtered to county 027 or the ODOT bridge layers.
- Hub v3 search API (`/api/v3/datasets?q=`) returns global results, not site-scoped, so do not rely on it for Norman discovery. The services directory listing is the reliable inventory.

### A6. OpenStreetMap Overpass (signals and more)

Overpass endpoints were unreachable from this sandbox (overpass-api.de connection reset, kumi.systems timeout). The queries below are standard and will work from a normal machine or in a GitHub Action.

```
[out:json][timeout:60];
area["name"="Norman"]["admin_level"="8"]["boundary"="administrative"]["is_in:state"="Oklahoma"]->.a;
(
  node["highway"="traffic_signals"](area.a);
  node["crossing"="traffic_signals"](area.a);
  node["railway"="level_crossing"](area.a);
);
out body;
```

For speed limits and lanes as a cross-check on Street_Centerlines:

```
[out:json][timeout:90];
area["name"="Norman"]["admin_level"="8"]->.a;
way["highway"~"^(motorway|trunk|primary|secondary|tertiary)(_link)?$"](area.a);
out tags geom;
```

Alternatives: `osmnx.features_from_place("Norman, Oklahoma, USA", {"highway": "traffic_signals"})` (see C), or the Geofabrik Oklahoma extract `https://download.geofabrik.de/north-america/us/oklahoma-latest.osm.pbf` with `osmium tags-filter`. License ODbL, credit "© OpenStreetMap contributors".

Caveat for the signal count: the City says 168+ signals including pedestrian signals. OSM tends to under-tag minor signals and over-tag by placing one node per approach on divided roads, so cluster nodes within 40 m before counting.

### Design moves distilled (across references)

- Basemap: either near-black with roads at 10 to 15% gray (deck.gl, Strava, TomTom) or warm off-white with ink-gray roads (SDOT, editorial). Never the default Mapbox Streets look.
- Congestion ramp: TomTom and Google use green, yellow, orange, red by speed ratio. For a V/C ratio ramp that reads as professional, use a single-hue or two-hue sequential (e.g. pale sand to deep crimson) and reserve pure red for the top decile only. Avoid rainbow.
- Line width: scale by AADT with `interpolate` on zoom, min 1.5 px, max 10 px at z14. Glow is two layers: an under-layer 2.5x wider at 15 to 25% opacity with `line-blur` 4 to 8, plus a crisp core.
- Animated flow: deck.gl TripsLayer for trips, or Mapbox `line-dasharray` animation on a `requestAnimationFrame` loop for direction, or `line-gradient` progress reveal for a single route.
- Labels: a grotesk or geometric sans for UI, tabular figures for numbers, 11 to 12 px map labels with 1 to 2 px halo.
- Panels: one left or right rail, 320 to 380 px, with a ranked list that highlights on hover and flies the map to the segment. Keep the map at least 65% of width.
- Legend: inline chips (Felt) or a thin ramp with 3 ticks (deck.gl), placed bottom-left, never a boxed Esri legend.
- Timeline scrubber: kepler.gl's bottom brush with a histogram behind it is the gold standard. For a 5-year bond schedule, a stepped scrubber with year labels and a play button is enough.
- Before and after: two synced maps side by side (editorial) or a single map with a drag slider (Mapbox compare plugin https://github.com/mapbox/mapbox-gl-compare, KNOWN). For plan changes (2025 Plan vs Proposed Functional Classifications) use dashed vs solid on one map.

### Three candidate directions

**Direction 1, "Operations console dark"** (TMC companion)

- Palette: background `#0B0E13`, surface `#131821`, hairline `#1F2733`, text `#E6EAF0`, muted text `#8A94A6`, roads base `#2A3340`, accent crimson `#C8102E` (hot), ramp sand `#E8D9B5` to amber `#F2A33A` to crimson `#C8102E` to deep `#4E0002`, positive teal `#2DD4BF` for "improved after".
- Type: Space Grotesk (display, 600) with IBM Plex Mono for numbers and labels, or Inter Tight with JetBrains Mono. All on Google Fonts.
- Basemap: Mapbox Standard with `theme: "monochrome"`, `lightPreset: "night"`, `show3dObjects: false`, or classic `mapbox://styles/mapbox/dark-v11` with road layers desaturated. Add the Norman `Building_Footprint` as a fill-extrusion at 25% opacity using BuildingHeight.
- Memorable detail: segments pulse (glow under-layer opacity 0.15 to 0.35 on a 2 s sine) only in the top ten, and the ranked rail shows a live-style "signal status" chip per segment using Intersection_Control counts from crash records.
- Risk: dark decks project poorly in bright rooms, and faculty judges may read "gamer" if the glow is overdone.

**Direction 2, "Editorial light, ink and one accent"** (the policy brief)

- Palette: paper `#F6F3EC`, panel `#FFFFFF`, ink `#1A1A1A`, road ink `#B8B2A6`, water `#DCE6EC`, muted `#6B6B6B`, accent crimson `#841617` (OU Crimson, AAA on white at 9.9:1), ramp cream `#F0E6D2` to clay `#D9A066` to crimson `#841617` to dark crimson `#4E0002`, secondary accent sky `#BCDCEB` for "funded" segments.
- Type: Fraunces or Instrument Serif for headlines, Inter or Public Sans for UI, tabular lining figures. Google Fonts.
- Basemap: Mapbox Standard `theme: "faded"` with `lightPreset: "day"`, labels off below z13, or classic `mapbox://styles/mapbox/light-v11`.
- Memorable detail: annotation leader lines drawn with SVG over the map that name the top three segments in the serif face, like a newspaper graphic, and a "Sources" footer line in small caps citing City of Norman, ACOG, ODOT.
- Risk: can feel static; needs the animated flow layer to still feel like a product.

**Direction 3, "Engineering drawing"** (the plan sheet)

- Palette: blueprint paper `#F2F1EC`, drawing ink `#1F2A44`, grid `#D8D5CC`, accent safety orange `#F26B1D`, ramp gray `#C9CDD6` to steel `#5B6B8C` to ink `#1F2A44`, callouts in orange only.
- Type: IBM Plex Sans Condensed for titles (uppercase, tracked), IBM Plex Mono for dimensions and values.
- Basemap: custom Mapbox Studio style from Light with all fills removed, roads as single ink casings, a faint 1-mile section grid drawn from `Section_Township_Range`.
- Memorable detail: each segment gets a "station" label like a plan sheet (STA 12+00), and the ranking table looks like a title block in the corner with revision marks for the 2026 bond years.
- Risk: niche, and harder to make the congestion ramp read without color.

**Recommendation: Direction 2 with a Direction 1 opener.** Reasoning for a 5 to 10 minute talk to MIS faculty and City engineers: the light editorial map reads clearly on a projector, OU Crimson is sanctioned for digital (Cream is not, see D), a single accent makes the ranking the hero, and it still supports glow and animated flow on a light map (use darker, more saturated glow, not white). Open with 15 seconds of the Standard `night` preset flying from I-35 into Campus Corner with the TripsLayer, then cross-fade to the light analytical view for the rest. Both views share the same crimson ramp so it reads as one product.

## Gaps and blocked items (for the spec)

1. ACOG MS2 TCDS (https://acog.public.ms2soft.com/tcds/tsearch.asp?loc=Acog&mod=) returns 403 to scripts; needs a browser session to export Norman count stations. This is the only place Norman's own recent counts live.
2. Overpass endpoints unreachable from this sandbox; queries are written above and will run elsewhere.
3. Census API requires a key now (302 to "Missing Key"); ACOG's `Census_Tracts_-_2020` and TIGER zips cover geometry and 2020 population without it.
4. City Conditions and Use Policy page would not scrape; only the search snippet confirms the logo restriction.
5. No public GIS for Norman traffic signals; the ACOG crash table's `Intersection_Control` and OSM are the substitutes.
6. ODOT Spotlight AADT app returns 403; the `AADT_Network` FeatureServer is the usable equivalent.
7. ODOT ATR hourly data is not public; request from ODOT or ACOG if a diurnal profile slide is wanted.
